# Make content, not code

Most of Synmergia is authored data. Classes, skills, items, enemies, quests, zones, NPCs, dialogue, mounts, achievements, and world content live under `game/data/` as Godot `.tres` resources. The website's Codex is generated from that same data.

This is the bridge between a player who wants to add something to the world and a contributor who wants to work in the repository.

## The shape of the data

| Content | Where it lives |
|---|---|
| Classes, species, skills | `game/data/classes/`, `game/data/species/`, `game/data/skills/` |
| Items and loot | `game/data/items/` and the loot tables under `game/data/` |
| Enemies and bosses | `game/data/enemies/` |
| Quests, dialogue, NPCs | `game/data/quests/`, `game/data/dialogues/`, `game/data/npcs/` |
| Zones and landmarks | `game/data/zones/`, `game/data/landmarks/` |
| World declarations | `game/data/` world resources such as `world_main.tres` |
| Art and models | `art/` for source, `game/models/` and `game/assets/` for shipped assets |

The schema files under `game/core/schemas/` are the field-level source of truth. If a field is not read by a service, do not assume it is live just because a resource authors it.

## The authoring loop

1. Edit the `.tres` resource under `game/data/`.
2. Regenerate the website data:

   ```bash
   npm run sync:data
   ```

3. Build or test the affected system:

   ```bash
   npm run build
   sh ./scripts/godot_test_runner.sh
   ```

4. Commit the `.tres` change and the regenerated `src/data/godot_data.json` together.

Never hand-edit `src/data/godot_data.json`; it is generated by `scripts/sync_godot_data.ts` from the resources.

## The rules that bite

- **One id style.** Filenames and ids follow the conventions in `AGENTS.md`; do not add a fallback parser for a second format.
- **References must resolve.** Quest targets, dialogue NPC ids, zone rosters, and loot references are checked by `test_data_naming_lint.gd`.
- **The Codex must stay honest.** If the data says it, the Codex reads it. If the Codex shows it, the data backs it.
- **Do not add a field without a reader.** Confirm the service or UI actually consumes it before treating it as a live contract.
