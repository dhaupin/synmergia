# Synmergia Web Client

Cloudflare-hosted HTML5 client for the Synmergia MMORPG.
Built on Godot 4.7.2's HTML5 export with a custom shell.

## Directory Structure

```
web/
├── index.html          # Main page with canvas + Godot init
├── config.js           # Server URLs and engine options
├── style.css           # Loading screen, error screen, FPS counter
├── wrangler.toml       # Cloudflare Workers config
├── worker.js           # Cloudflare Worker (static + WebSocket proxy)
├── game.js             # Godot JS glue (generated by export)
├── game.wasm           # WASM binary (generated by export)
├── game.pck            # Packed resources (generated by export)
├── icon.svg            # Favicon (copied from game/icon.svg)
└── shared/
    └── input.js        # SynmergiaInput capture layer (buffered events)
```

## Input architecture (important)

The Godot web runtime delivers mouse/touch/keyboard **natively**; a plain
export does not need `shared/input.js`. Two paths exist:

1. **Standalone page (`index.html`)**: native engine input. The capture
   layer is loaded but NOT auto-initialized -- initializing it here would
   double-deliver every event.
2. **Embedded/wrapper contexts** (portal `GodotCanvas.tsx`, 2D companion
   client per `labs/prd-web.md`): the wrapper calls
   `SynmergiaInput.init(canvas)` to buffer events; the engine-side
   `WebInputBridge` autoload drains them each frame via
   `window.SynmergiaInput.drain()` and feeds `Input.parse_input_event()`.

The event contract is documented at the top of both
`web/shared/input.js` and `game/core/autoload/web_input_bridge.gd`
(types 1-12; keys carry keyCode in `x`, modifier bitmask in `y`, unicode
in `data`; wheel sends 3/4 with no release). Both sides are locked by
tests: `game/tests/test_web_input_bridge.gd` (GDScript conversion) and
the node contract test used in CI reviews.

## Building

### Prerequisites
- Godot 4.7.2 with HTML5 export template installed
- Node.js (for wrangler)

### Steps

1. **Install Godot HTML5 export template** (if not already):
   ```bash
   godot --headless --export-template
   ```

2. **Export the game**:
   ```bash
   cd game
   godot --headless --export-html5 ../web
   ```
   This generates `game.js`, `game.wasm`, and `game.pck` in `../web/`.

3. **Copy icon**:
   ```bash
   cp game/icon.svg web/icon.svg
   ```

4. **Deploy to Cloudflare**:
   ```bash
   cd web
   npm install
   wrangler deploy
   ```

### Environment Variables

Set these in `wrangler.toml` or via `wrangler secret put`:

| Variable | Description | Default |
|----------|-------------|---------|
| `SERVER_URL` | WebSocket server URL | `wss://synmergia.example.com/ws` |
| `API_URL` | REST API URL | `https://api.synmergia.example.com` |
| `DEBUG` | Enable debug output | `false` |

## Architecture

- **Input**: Shared `Int32Array` buffer for mouse/touch/keyboard events
- **Network**: `WebSocketMultiplayerPeer` for Godot's high-level multiplayer API (RPC, state sync)
- **Rendering**: Godot WASM with HTML5 canvas
- **Hosting**: Cloudflare Workers with static asset caching

### Input Flow

1. Browser events → `shared/input.js` → `Int32Array` buffer
2. `WebInputBridge` autoload polls JS buffer every frame
3. Converts events to Godot `InputEvent` types
4. Pushes into Godot's input system via `Input.parse_input_event()`

### Network Flow

1. Godot `WebSocketMultiplayerPeer` → WebSocket frames (via worker proxy)
2. Godot's high-level multiplayer API manages peer state
3. Server-side `NetworkManager` auto-starts in headless/prod mode

## Browser Support

- WebAssembly (all modern browsers)
- WebSocket (all modern browsers)
- Touch support (mobile Safari, Chrome)
- Minimum: Chrome 89+, Firefox 89+, Safari 14+, Edge 89+

## Export Presets

The `game/export_presets.tres` file defines the HTML5 export configuration:
- Platform: Web
- Format: PCK (packed)
- Texture compression: ETC2/ASTC
- Worker enabled for better performance
- Canvas size: 1280x720
- Output path: `../web/game.pck`
